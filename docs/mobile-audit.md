# DayFlow 移动端优化分析

> 基于当前代码（`index.html` / `style.css` / `app.js`，提交 6412ea5）与 390×844、320×568 实测数据。
> 视觉体系保持不变：#F5F5F7 画布、#1D1D1F 墨色、#0066CC 交互蓝、18px 卡片圆角、pill 按钮、1px hairline。

---

## 一、结论摘要

**已经成立的**：移动端不是把桌面压缩，而是重做了一套结构（黑条导航 + 日期头 + 进度条 + 分段筛选 + 全宽时间线），设计语言与桌面一致；空态、搜索、抽屉、常用内容、日期切换都可用；不依赖任何外部字体和 CDN，首屏 DCL 9ms / load 18ms / 首次绘制 64ms，性能底子很好。

**三个真正的短板**：

1. **功能不对称**：手机能新增常用内容，但删不掉（管理入口在桌面左栏里）。
2. **单手操作不达标**：核心触控目标普遍 15–28px，远低于 44px；新建面板一打开就弹键盘，保存按钮落在屏幕外。
3. **滚动中失去上下文**：日期、进度、筛选在滚动 300px 后全部离场，时间线中段不知道"这天是哪天、还在哪个筛选下"。

## 二、实测基线（390×844 / 320×568，9 条任务）

| 指标 | 390×844 | 320×568 | 说明 |
|---|---|---|---|
| 首屏 chrome 高度（导航→工具条） | 212px（25.1%） | 212px（37.3%） | 320 屏近 4 成屏幕被头部占用 |
| 最短任务行高 | 28.8px | 28.8px | 15 分钟任务，低于 44px 触控基线 |
| 勾选圈 | 15×15 | 15×15 | 视觉与热区同为 15px |
| 搜索 / 视图切换 / 关闭 | 26 / 26 / 28 px | 同 | 均 < 44px |
| 自动排程 / 一键清空 | 46×16 | 46×16 | 纯文字链接，相邻仅 10px |
| 最小字号 | 9px（优先级标签） | 9px | 时长 10px、时间 11px、描述 11px |
| 首屏 DOM 节点 | 486 | 486 | 全量重建耗时 2.4ms，CPU 不是瓶颈 |
| 横向溢出 | 无（390=390） | 无（320=320） | 布局本身是干净的 |

## 三、优化建议

### P0 · 先修，直接影响可用性（约 1 天）

| # | 问题与依据 | 具体改法 | 预期收益 |
|---|---|---|---|
| 1 | **移动端无法删除常用内容**。`#quickManage` 在 `.rail` 内，`.rail` 在 <900px 为 `display:none`，但 `data-quick-new` 在抽屉里可用 → 只能加不能删，到 `QUICK_MAX=24` 后彻底锁死。 | 移动端在「常用内容」chips 行标题右侧放「管理」，复用 `ui.managing` 与 `data-quick-del`；或长按 chip 进入删除态（700ms 长按 + 触感反馈）。 | 消除功能黑洞；常用列表长期可维护，不会越积越乱。 |
| 2 | **打开新建面板即弹键盘，保存按钮在屏幕外**。`openDrawer()` 320ms 后 `fTitle.focus()`；390×844 下面板高 776、内容 899，「保存安排」位于 y=908；键盘弹出后可视区仅剩 396px，需滚动约 500px 才能保存。 | 移动端不自动聚焦（`if (!isMobile()) fTitle.focus()`）；viewport 增加 `interactive-widget=resizes-content`；抽屉高度改为 `min(92dvh, calc(100vh - 12px))` 并监听 `visualViewport` 收缩；底部操作条 `position:sticky;bottom:0` 常驻。 | 新建路径少 2 步；消除"看不到保存按钮"的挫败感，这是移动端最高频动作。 |
| 3 | **触控热区普遍不足**。搜索 26×26、视图切换 26×26、关闭 28×28、筛选 35 高、勾选 15×15、自动排程 46×16。 | 视觉尺寸不变，用 `::after{content:'';position:absolute;inset:-14px}` 或 padding 把热区补到 ≥44×44；勾选圈外层加一个 44px 的按钮容器；破坏性操作（删除、一键清空）在移动端收进「···」菜单，不与安全操作并排。 | 误触率明显下降，尤其是勾选和清空这类不可逆动作；单手拇指可达性达标。 |
| 4 | **短任务信息被砍**。`dur ≤ 45` 进入 `.short` 布局，行高 = 18 + dur×0.72（15 分钟仅 28.8px），且 `.short .ptag{display:none}`，优先级与时长信息在手机上消失。 | 移动端行高 `min-height:44px`；短任务用单行 `10:30 晨会 · 15m · 高` 的紧凑排版保留全部信息；时长 ≤15 分钟仍可与前一项合并显示。 | 时间线可扫读、可点击；优先级在手机上不再丢失（这是筛选之外唯一的优先级表达）。 |

### P1 · 体验质量与移动端"原生感"（约 1.5 天）

| # | 问题与依据 | 具体改法 | 预期收益 |
|---|---|---|---|
| 5 | **滚动后上下文丢失**。`.mnav` sticky，但 `.mhead`/`.mfilter` 不 sticky：滚动 302px 后 head 顶部 -254、filter -181，时间线中段既无日期也无筛选态。 | 滚动超过 40px 时把 `.mhead` 折叠为 44px sticky 条（日期 + 完成率 + 视图切换），`.mfilter` + `.mtools` 作为第二层 sticky，`backdrop-filter: blur(12px)` + 半透明 `rgba(245,245,247,.82)`。 | 长日程滚动中始终知道"哪天、多少完成、在哪个筛选下"；同时把 212px chrome 压到 ~100px，首屏多出约 1.5 行任务。 |
| 6 | **日期切换只有原生日历一条路**。无左右按钮、无手势、也看不到"哪几天有安排"。 | 日期行左侧加 44px 热区箭头；增加 7 天横向日期条（圆点标记有安排的日子，今天加实心点）；支持内容区左右滑动切日（阈值 60px，纵向滚动优先）。 | 手机上最高频操作从"点日期→滚轮→确认"3 步降到 1 步；能一眼看到本周哪天空。 |
| 7 | **不定位当下**。9 条任务打开时从 08:00 开始，若当前 15:00，「现在」线可能在两屏之外。 | 首次进入（今天 / 时间线视图）自动滚到 `.now-row` 上方 1/3 处；滚动离开后 FAB 上方浮出「现在」小胶囊，点回。 | 打开即见当下，符合"安排今天"的心理模型。 |
| 8 | **清空 / 删除不可撤销**。清空只有 2 次点击 + 3.2s 窗口，完成态只有 2s toast，无撤销。 | toast 支持一个动作按钮：完成 →「撤销」，清空 →「恢复」（保留被删数组 5s）；移动端把「一键清空」移入「···」。 | 降低误触成本，用户敢于操作；破坏性动作与「自动排程」不再并排。 |
| 9 | **搜索与上下文不一致**。占位文案固定「搜索今天的安排」，切到其他日期仍显示；切日期会清空关键词但搜索条保持展开；逐字符重建整个列表。 | 文案按 `S.date === todayKey()` 动态化；输入 180ms 防抖；命中数显示在输入框右侧（`3 条`）；切换日期时顺带收起搜索条。 | 文案与状态一致；输入更顺滑，长列表下不再每键重建。 |
| 10 | **空闲时长口径不对**。筛选「已完成」时 chip 显示「空闲 9h30」，因为 `freeMinutes()` 用的是 `visibleTasks()`。 | 改为按全天任务计算，或在非「全部」筛选下隐藏该 chip。 | 数据可信，不出现"空闲 9 小时却排满了"的矛盾。 |
| 11 | **移动端卡片的"浮起感"被抹平**。`.tl-card` 外壳透明化后，任务卡只剩 12px 圆角 + 1px 线，与桌面 18px 卡片的层次语言断开。 | 任务卡移动端圆角回到 14px，加 `0 1px 2px rgba(29,29,31,.04)`；分组（上午/下午）用 18px 大卡包裹，形成两级层次。 | 与设计稿的视觉血缘延续，长列表分组后可读性显著提升。 |

### P2 · 工程与打磨（约 1 天）

| # | 问题与依据 | 具体改法 | 预期收益 |
|---|---|---|---|
| 12 | **iOS 聚焦缩放**。`#fDesc` 计算字号 14px < 16px，iOS Safari 聚焦时会自动放大整页。 | 移动端 textarea 字号 16px（或 `font-size:16px` + 视觉行高不变）。 | 输入时不再跳版。 |
| 13 | **"加到主屏"是个空壳**。`apple-touch-icon` 指向 SVG（iOS 不支持，图标会退化为截图），manifest 只有 SVG 图标，且没有 service worker → 断网打不开。 | 补 180/192/512 PNG + maskable 图标；注册 SW 缓存应用壳（HTML/CSS/JS/图标），用版本号做更新策略；断网时给出"离线可查看，改动会在恢复后保存"的提示。 | 真正的"主屏 App"观感；弱网/地铁场景秒开，首字节从网络往返变成缓存命中。 |
| 14 | **全量重建导致焦点丢失**。每次勾选 `renderAll()` 重建 486 节点，实测勾选后原节点已不在 DOM，焦点回到 `BODY`；屏幕阅读器朗读中断。移动端还会渲染不可见的 `.rail` 与近 7 天柱状图。 | 勾选改为就地 patch（切 class + 更新 aria-pressed），筛选只重建列表；移动端跳过 rail / week 的渲染（或改为抽屉内按需渲染）；重建后恢复焦点。 | 无障碍体验正确；为未来任务量增长留出余量（当前 2.4ms 尚不是问题，属于预防性投入）。 |
| 15 | **面板细节**。`body.no-scroll` 在 iOS 上不能完全锁住背景滚动；抽屉缺 `overscroll-behavior:contain`；`body` 底部留白 96px 未含 `safe-area-inset-bottom`；全站没有 `-webkit-tap-highlight-color:transparent`，点按有灰色方块闪烁。 | 抽屉加 `overscroll-behavior:contain`；底部留白 `calc(96px + var(--safe-b))`；全局关闭 tap highlight，改用 `:active` 的既有反馈。 | 面板不再"透"滚动；全面屏底部不被 FAB 压住；点按质感更接近原生。 |
| 16 | **时间标尺只读**。`#ruler` 高 46px 只做展示，手机上调整时间仍要开两个滚轮选择器。 | 标尺支持拖拽两端调整起止（pointer events，吸附 5 分钟），拖动时给出 haptic 与时间气泡；保留时间输入作为精确输入。 | 时间选择从"两次滚轮"变成"一次拖拽"，这是移动端最值得投入的手势增强。 |

## 四、落地顺序建议

- **第 1 轮（P0 #1–#4）**：功能补齐 + 触控达标 + 新建流程。改完立刻能在手机上感受到差别，风险最低。
- **第 2 轮（P1 #5–#9）**：折叠头 + 日期条 + 定位当下 + 撤销。这一轮决定"像不像一个原生 App"。
- **第 3 轮（P2 #12–#15）**：图标 / Service Worker / 渲染策略 / 面板细节。偏工程，可与第 2 轮并行。
- **可选增强（#16 标尺拖拽）**：等前两轮稳定后再做，属于加分项。

## 五、不建议做的

- 不引入 UI 框架或组件库：当前 0 依赖、单文件即可部署，是这类工具的优势。
- 不把桌面左栏（进度 / 近 7 天 / 小技巧）平移到手机主流程：它们会挤掉时间线，应放进「统计」二级页或抽屉。
- 不做底部 Tab 栏：只有"今日"一个主场景，加 Tab 反而制造空转。
- 不为移动端另起一套视觉：现有 token 足够，问题在尺寸、热区和状态，不在配色。
